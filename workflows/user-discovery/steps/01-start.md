# 01, Start and Maturity Level

## Objective

Create the working folder, understand what the user brings, and locate the maturity level.

## Method notes

- First understand whether the person is just starting, has already tried something, or already knows their users.
- Don't begin with solutions.
- The guide explains the process and asks for active involvement.

## Documents to touch

- `discovery/challenge.md`
- `discovery/_system/state.yaml`
- `discovery/_system/decisions.md`
- `discovery/_system/assumptions.md` if you advance with assumptions

## Guiding questions

- What do you want to understand or improve?
- What level are you at: 0 to 5?
- What material do you already have?
- What is out of scope for this discovery?

## Using the template

Fill out in `challenge.md`:

- Project objective.
- Maturity level and evidence.
- Initial context.
- Scope and out of scope.

If the user brings documents, log them in `_sources/knowledge-base.md` as loaded sources.

## Gate

Recommended status:

- `capturing` if context is missing.
- `drafted` if there is an objective, level, and scope.
- `validated` if the user confirms.
- `advanced_with_assumptions` if you move forward without closing scope.

Suggested default action: `Deepen`.

## Checklist before advancing

- There is an understandable objective.
- There is a justified 0-5 level.
- It is clear we are not looking for solutions yet.
- There is a first list of materials or missing context.
