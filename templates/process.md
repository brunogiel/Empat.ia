# Field Checklist

This document keeps you from improvising interviews. Use it before, during and after every field outing or call.

## Before

### Research preparation

- [ ] Design Challenge visible.
- [ ] Learning objectives clear.
- [ ] Interviewee profile reviewed.
- [ ] Corresponding guide ready.
- [ ] Roles defined: who asks, who takes notes, who observes.
- [ ] Recording or note-taking tool tested.
- [ ] Plan B if the tech fails.

### Privacy and consent

- [ ] Explain the purpose without selling or biasing.
- [ ] Ask permission to record.
- [ ] Ask permission for photos if applicable.
- [ ] Avoid photos of faces or sensitive information if there is no explicit permission.
- [ ] Clarify whether real names or anonymous names will be used.

### Context

- [ ] Interview them in their real environment if possible.
- [ ] Prepare questions about objects, documents, spaces or tools.
- [ ] If it's in person, bring a notebook, pen and battery.

## During

- [ ] Start with rapport.
- [ ] Remember the interviewee is the expert.
- [ ] Ask open questions.
- [ ] Ask for recent examples.
- [ ] Ask why.
- [ ] Ask "show me" if there's an object, document or flow.
- [ ] Record verbatim quotes.
- [ ] Observe the environment, body language, tools and workarounds.
- [ ] Let the conversation drift if something valuable shows up.
- [ ] Don't judge.
- [ ] Don't correct.
- [ ] Don't finish their sentences.
- [ ] Don't validate a solution.

## After, within 24 hours

- [ ] Save audio/video/notes with date, profile and anonymous name.
- [ ] Write down 5-10 strong verbatim quotes.
- [ ] Write down interviewer observations, separated from what the user said.
- [ ] Note moments of tension, surprise or emotion.
- [ ] Record new questions.
- [ ] Update the recruitment tracker.
- [ ] Mark sample gaps.

## Suggested naming convention

```text
YYYY-MM-DD_profile_anonymous-name_type.md
```

Example:

```text
2026-05-11_logistics-sme_e01_notes.md
```

## Mistakes to avoid

- Asking closed questions.
- Leading the answers.
- Talking more than listening.
- Racing through the guide without going deeper.
- Looking for them to confirm what we want to hear.
- Treating experts or benchmarks as a substitute for users.
